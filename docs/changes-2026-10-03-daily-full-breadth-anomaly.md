## 3. 根因

**两个因素叠加**：

1. **日更链路用窗口式增量更新**
   `每日行业报告.command:97`：`build_industry_daily_full.py --days 60`
   而 `build_industry_daily_full.py` 的 upsert 逻辑是：
   ```python
   kept   = prev[~prev[key].isin(daily[key])]   # 窗口外的历史：原样保留
   merged = concat([kept, daily]).drop_duplicates(key, keep="last")
   ```
   ⇒ **窗口外（>60 个交易日前）的历史永远不会被重算**。

2. **上游行情数据当时不完整**
   `market/daily/` 中 **2026-05 ~ 2026-09 的全部文件 mtime 都是 `2026-09-23 22:52`**
   ⇒ 这批行情是在 **09-23** 才被重写/回填的。
   ⇒ 07-01~07-13 期间跑日更时，MA20 取不到足够历史 ⇒ 宽度算不出
   ⇒ 落到 `daily_full` 里就是 **0**（而非 NaN）。

3. **坏值固化**：09-23 补全行情后，日更的 60 日窗口已滚过 07-01~07-13
   ⇒ **再也不会被重算**。截至 09-30 的产物仍带着这 9 天坏值。

> ⚠️ **通用教训**：**窗口式 upsert（`--days N`）× 上游数据延迟补齐 = 不可逆的历史坏值。**
> 坏值一旦滚出窗口就永久固化，而现有 `check_data_completeness.py` **只校验"有没有/空不空"，
> 抓不到"有行但值坏"** —— 这正是 C4 要补的能力。

## 4.5 补充实测（2026-10-03 晚，落护栏前）

| 检查 | 结果 |
|---|---|
| **坏值可否复现** | ❌ **不能**。用当前 `market/daily` 以 `end_date=2026-07-13` 分别取 9 / 13 / 20 / 40 / 60 / 250 日窗口重算，`breadth==0` 占比只有 **6.1% / 4.4% / 9.8% / 10.9% / 10.9% / 10.9%** ⇒ 现状数据在任何窗口下都**不产生**全 0 宽度。坏值是**当时运行时状态**的产物，现已不可重建 |
| **坏值的确切形态** | `breadth` 与 `breadth_ma13` **精确等于 `0.0`**（不是 NaN），131 行业 × 9 天 = **1179 行全为 0**；同段 `avg_pct`（−8.75 ~ +10.36）、`total_amount`、`n_stocks`（2 ~ 244）全部正常 |
| **同链路的 `weighted_returns` 是否同病** | ✅ **否**。2026-07-01~07-13 段 `weighted_pct` / `circ_mv` / `stock_n` **NaN 与 0 均为 0 行**，std 与对照段（06-15~06-30）同量级；全历史扫描**无一天**退化 ⇒ 该产物不经 MA 预热，**不受此机制影响** |
| **0 vs NaN 的语义** | 精确的 `0.0` 对应**旧代码语义**（`above_ma20 = (close > ma20).astype(int)`，ma20 未成型时 `close > NaN` → False → 0）。2026-10-01 起改为 `breadth_dropna` 后，同样场景会产出 **NaN** ⇒ **护栏必须同时抓 0 与 NaN** |

> ⚠️ 由于坏值不可复现，**护栏无法用真实数据做端到端"退化"验证**，只能：① 用构造输入做单元验证
> （8 个用例，见 §5.2）；② 用真实数据验证**正常路径零回归**。

## 5. 修复与防御

### 5.1 ✅ 写入护栏已落地（2026-10-03，`scripts/build_industry_daily_full.py`）

**决策（主人 2026-10-03）**：**先加拒写护栏，不重算历史坏值**；`--days 60` 窗口参数**暂不动**。

在 `compute_concept_daily()` 之后、upsert **之前**插入 `_preflight_guard()`，三条判据（顺序即优先级）：

| # | 判据 | 阈值 | 为什么这样定 |
|:--:|---|---|---|
| ① | 行情窗口交易日数 | `< 33` 即拒 | breadth 依赖 MA20/MA13，模块 docstring 已写明「需 ≥33 天预热」 |
| ② | 窗口起点 == 行情最早日 | 命中则**豁免** | 全历史重建时 MA 未成型属正常（正是 `2020-01-02~01-07` 那 4 天） |
| ③ | 「`breadth` 为 **0 或 NaN**」的行业占比，**逐日取中位数** | `≥ 0.80` 即拒 | 用**中位数**而非均值/最大值：单日市场级跌停（`2020-02-03` 实测 56.5%）是**真实行情**，不该触发；坏值场景是**每一天都接近 100%** |

- `--force-overwrite` **跳过全部判据**（整表重建，早期日期宽度低属正常）。
- 拒写时打印排查顺序（上游是否缺文件/文件不全 → `--days` 是否过小 → 是否该用 `--force-overwrite`）并 `return 1`。
- ⚠️ 判据 ③ **必须同时抓 0 与 NaN**（见 §4.5 末行）—— 只判 `== 0` 会漏掉现行 `breadth_dropna` 语义下的 NaN。

**验证**：

| 项 | 方法 | 结果 |
|---|---|---|
| 单元（8 用例） | 构造 `daily`/`mkt` 调 `_preflight_guard` | A 正常~10% ✅通过 ｜ B 全0 ✅拒 ｜ **G 全NaN ✅拒** ｜ H 0/NaN 混合94% ✅拒 ｜ C 行情10天 ✅拒 ｜ D 数据起点 ✅豁免 ｜ E 单日56.5% ✅通过 ｜ F `--force-overwrite` ✅跳过 → **8/8** |
| 正常路径**零回归** | 同源 A/B：`--days 60`，基线代码（`git show HEAD:` 版）vs 改后 | 产物内容 sha **`6f1bbce75dead90b` 完全相同**，214,316 行逐行逐列一致 |
| 真实拒写 | `--days 10` | `exit=1`，打印「行情窗口仅 10 个交易日 < 33 天」，且**输出目录未创建** |
| 真实数据根守卫 | `touch` marker → 跑 → `find ~/quant-data -newer marker` | **零输出**（未写真实数据根） |
