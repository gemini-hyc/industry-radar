# 信号台账与评估框架（P0）

> 创建日期：2026-09-23
> 定位：把"信号到底行不行"从反复争论变成一条可每日更新、与数据同源的结论
> 代码：`src/signals/`（ledger / sources / evaluate）+ `scripts/build_signals_log.py` / `scripts/evaluate_signals.py`

---

## 一、为什么需要它

改造前的问题不是"没有信号"，而是**信号无法被验证**：

1. **没有 follow-through**：信号发出后无人跟踪对错。2026-09-21 航空机场发出冷区信号、09-22 因扩张结束而消失，没有任何地方记录它后来涨了还是跌了。
2. **结论散落且不可复现**：回测结论散在 `research/`（40+ 冻结脚本）与 `docs/`，数据地基一变（成分口径、加权方式、聚合方式都改过）就无法复算。文档内部也自相矛盾——`module_02_rebuild.md` 规定冷区信号按 4 个质量维度打 2~13 分，`factor_width_reversal.py` 的 v3 却砍掉了其中 3 个维度、改为只按前20日均宽分级。
3. **条件信号不能用 IC 评估**：信号只在特定状态触发，IC 会被零值稀释（文档里已认识到这点），但没有建立替代框架。

台账的作用：**任何信号先入账，再由统一评估器回填前向收益**。模型可以换、参数可以调，但"证据"必须落在同一个地方。

## 二、设计

### 表结构 `signals/signals_log.parquet`

| 列 | 含义 |
|---|---|
| `signal_date` | 信号日 |
| `source` | 来源：`cold_zone` / `tracker_pool` / `mainline` |
| `obs_type` | `event`（一次性事件）/ `state`（每日状态快照） |
| `ind_code` / `ind_name` | 行业代码（== `industry_list.ts_code`）/ 名称 |
| `score` | 数值强度（口径随来源，见下） |
| `tier` | 分级标签（冷区为 high/standard/watch） |
| `features` | JSON 特征快照（前宽、D1占比、量比、拥挤度等） |
| `logged_at` | 入账时间（审计） |
| `fwd_ret_{5,10,20,60}` | 信号日 T+1..T+h 逐日加总的收益（%） |
| `fwd_excess_{5,10,20,60}` | 同上减基准（pp） |

- **唯一键** `(source, signal_date, ind_code)`：重复写入幂等，元数据取最后一次、收益列保留已有非空值。
- **基准**：行业等权（全部行业当日加权涨跌幅的横截面均值），与项目内"行业超额"口径一致。
- **未到期**保持 NaN，宁可标注"未到期"也不臆造收益；`maturity_table()` 单独统计到期情况。

### 两类来源

| 来源 | 入账方式 | 原因 |
|---|---|---|
| `cold_zone` | **全历史回填**（2020-02 起 2234 条） | 信号完全由宽度序列决定，且回填直接复用生产函数 `factor_width_reversal.detect_signals`，保证台账与日报是同一个东西 |
| `tracker_pool` | 每日快照，以**入场事件**入账 | 有状态引擎，历史无法无损重建；重复快照按唯一键自动去重 |
| `mainline` | 每日快照，以**每日状态**入账 | 同上；成员行业经名称→代码映射展开 |

日频链路（`cron/industry_review_daily.py`）在**数据完备性检查通过之后**自动入账 + 回填收益，异常不影响主报告。

## 三、用法

```bash
# 首次：全历史回填（约 1~3 分钟，含拥挤度特征聚合）
python3 scripts/build_signals_log.py --backfill-cold-zone

# 日更：当日快照 + 前向收益回填（cron 已自动执行，一般无需手动）
python3 scripts/build_signals_log.py

# 评估：事件研究
python3 scripts/evaluate_signals.py
python3 scripts/evaluate_signals.py --source cold_zone --horizons 5,10,20,60
```

产出：`signals/signals_log.parquet`、`signals/eval_YYYYMMDD.md`。

## 四、首轮结论（2020-02-07 ~ 2026-09-21，2234 条冷区信号）

> 全部为**超额**口径（已扣除行业等权基准）；文档中"累计收益"口径的数字不可直接比较。

### 1. 总体：比文档记录的弱得多

| 持有期 | 样本 | 平均超额 | 中位超额 | 胜率 | t 值 |
|:---|:---:|:---:|:---:|:---:|:---:|
| 5日 | 2231 | +0.00pp | −0.15pp | 47.4% | 0.02 |
| 10日 | 2231 | +0.16pp | −0.22pp | 47.6% | 1.60 |
| 20日 | 2230 | **+0.31pp** | −0.02pp | **49.9%** | 2.25 |
| 60日 | 2070 | +0.67pp | −0.57pp | 47.6% | 2.61 |

对照 `module-02-backtest-findings.md` 记录的"仅触发 N=2432 / 20日 +2.02% / 胜率 62%"——**差异巨大**。注意三处口径差异（都不利于旧数字）：旧文档该表用的是"累计收益"而非超额；样本规则是"扩张≥3天"而生产规则是"恰好第 3 天一次性触发"；数据地基此后已重建（等权聚合、PIT 成分、`circ_mv` 加权）。

### 2. "越冷越强"仍然成立，但幅度小一个量级

| 档位（前20日均宽） | 样本 | 平均超额 | 胜率 | t 值 |
|:---|:---:|:---:|:---:|:---:|
| high（<10%） | 252 | **+1.21pp** | 55.2% | 2.86 |
| standard（10~20%） | 916 | +0.15pp | 49.7% | 0.70 |
| watch（20~30%） | 1062 | +0.23pp | 48.9% | 1.18 |

文档记录该档为 +9.06%/84%，现在只有 +1.21pp/55.2%（t=2.86，仍显著）。**方向对、强度远低于记录**。

### 3. 分年稳定性不成立

2022 年 +1.33pp（t=4.06）与 2026 年 +0.90pp（t=1.95）贡献了几乎全部正收益；2021（−0.30）、2024（−0.15）、2025（−0.19）为负，2023 近乎为零。文档中"三阶段全正向、跨阶段一致性是该信号核心竞争力"的结论**未复现**。

### 4. 最强的调制变量是 regime（也是最大机会）

| 信号日 regime | 样本 | 平均超额 | 胜率 | t 值 |
|:---|:---:|:---:|:---:|:---:|
| 全面上涨 | 1026 | +0.58pp | 50.9% | 2.71 |
| 混合 | 230 | +0.28pp | 50.0% | 0.70 |
| 偏弱轮动 | 235 | +0.27pp | 48.5% | 0.62 |
| 轮动 | 577 | +0.03pp | 51.0% | 0.14 |
| 全面下跌 | 162 | −0.32pp | 42.0% | −0.63 |

信号实质上是**顺市场状态**的：只在偏强市场有效，在全面下跌中为负。这与文档"子阶段调制是最核心发现、但未落地"的判断一致——现在有了可直接使用的条件变量。

### 5. 收益集中在右尾

中位超额在各持有期均 ≈0 或为负，均值靠少数极端成功案例拉动。这意味着**等权全买会摊薄**，落地时必须考虑选股/加权方式，以及少数样本的稳健性。

## 五、下一步（按性价比）

1. **补一个"≥3天"变体**：用同一台账复核旧文档的"扩张≥3天"规则（现在生产规则只取第 3 天），明确两者差异是规则还是数据造成的。
2. **把 regime 内生化**：将"全面上涨"作为冷区信号的前置条件或权重，再评估——这是当前最可能提升性价比的改动。
3. **向前积累 tracker_pool / mainline 样本**：这两者无法历史回填，只能靠日频快照（每天 20 条左右，一年约 5000 条），半年后即可做首轮检验。
4. **落地层**：定义可交易载体（ETF 映射 / 龙头组合）与持仓规则，否则超额再高也无法使用。
5. **生命周期模型化**：台账稳定运行后再替换手工阶段机（生存分析 / HMM），届时任何改动都能立刻看到它是否真的更好。

## 六、已知局限

- `tracker_pool` / `mainline` 只有向前样本，暂无统计意义（首轮快照分别 21 / 1 条）。
- 拥挤度特征在回填中按"行业内个股中位数"聚合，与 module_02 单日聚合口径一致，但历史上受成分数据可得性影响。
- 回填依赖 `industry_daily_full.parquet` 的完整历史；若日更任务改为只保留近 N 天，需在截断前完成回填（台账本身即为持久留痕）。
