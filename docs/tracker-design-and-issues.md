## 0. 一句话定位

**它想回答：一个长期"睡死"的行业，今天突然大涨——这是不是反转的起点？如果是，它现在走到哪一步了？**

它不是在预测"明天涨不涨"，而是给一个行业事件建**生命周期档案**：
`触发 → 逐日打分 → 趋势确认 → 主升 → 过热预警 → 衰退退出`。模块自称"系统A"。

**核心假设**（`:431`）：**前 20 日均宽 < 45%（沉睡） × 当日加权涨幅 > 1.5%（惊醒）**。

## 2. 第一层 · 入场：触发条件与初始分 S₀

`_check_reversal_conditions()` `:407-462`

### 2.1 四个条件（同时成立，`:420-432`）

| # | 条件 | 常量 | 含义 |
|:--:|---|---|---|
| 1 | 历史 ≥ **20** 个交易日 | — | 保证 20 日均宽可算 |
| 2 | 当日宽度 ≥ **15%** | `RETIRE_BW` | 反转过弱的不看 |
| 3 | 前 20 日均宽 < **45%** | `REVERSAL_BREADTH_MAX` | **"沉睡"判据** |
| 4 | 当日加权涨幅 > **1.5%** | `REVERSAL_PCT_MIN` | **"惊醒"判据** |

### 2.2 初始分：`S₀ = clamp( 放大器(C1) × 基础分(C3), 上限 100 )` `:80-81`

| 前 20 日均宽 | 放大器 `_amplifier_c1` | | 当日涨幅 | 基础分 `_base_c3` |
|---|---:|---|---|---:|
| <5% | **2.5** | | >5% | **40** |
| <10% | 2.0 | | >3% | 32 |
| <20% | 1.5 | | >2% | 24 |
| <35% | 1.2 | | >1.5% | 16 |
| <45% | 1.0 | | else | 0 |
| else | 0.5 | | | |

**设计意图 = 乘性**："睡得更死 × 涨得更猛 ⇒ 信号更强"。
例：前宽 8% + 涨 6% ⇒ `2.0 × 40 = 80`；前宽 40% + 涨 2% ⇒ `1.0 × 24 = 24`。

⚠️ 两个边界事实：
- 因条件 3 已限 <45%，**"2.5×/2.0×"两个深度档只在均宽 <10% 时才可能用到**（⚙️ 由档位推算）；
- `compute_S0` **只 clamp 上界，无下界**（`:81`）。

另外记 `entry_confidence = max(0.1, 1 − 拥挤度分位)`（`:437`）——**起涨时越不拥挤，置信度越高**。

状态初始化为 `status="triggered"`, `phase="early"`, `days=0`（`:439-457`）。

## 3. 第二层 · 打分：`Sₜ = Sₜ₋₁ × λₜ`

`_update_score()` `:566-596` ＋ `compute_lambda()` `:123-146`

```
Sₜ = clamp( Sₜ₋₁ × λₜ , 0, 100 )
λₜ = ( c₁ · c₂ · c₃ · c₄^0.6 ) ^ (1/3.6)
```

### 3.1 四个方向分量（每个都是 if-else 手写档位）

| 分量 | 输入 | 弱 ← 档位 → 强 | 位置 |
|---|---|---|---|
| `c₁` 宽度方向 | Δ宽度 (pp) | 0.5 / 0.8 / 1.0 / 1.2 / **1.4** | `:85-91` |
| `c₂` 涨跌方向 | 当日涨幅 | 0.4 / 0.7 / 0.85 / 1.1 / **1.3** | `:93-99` |
| `c₃` 量能方向 | 成交额(今日/昨日) | 0.7 / 0.9 / 1.1 / **1.3** | `:101-106` |
| `c₄` 拥挤度方向 | 拥挤度 − 前 5 日中位数 | 0.7 / 0.9 / 1.0 / 1.1 / **1.3**，且 **^0.6 折权** | `:108-121` |

### 3.2 为什么是 `^(1/3.6)` —— 这是本模块唯一"有设计感"的地方

权重 `1+1+1+0.6 = 3.6` ⇒ **加权几何平均**。效果是把 λ 压在 1 附近：

- **实测可达范围 λ ∈ [0.546, 1.327]**（500 种档位组合穷举）✅
- 全中性（四分量皆 1）⇒ λ = 1.000
- ⇒ **单日最多 +33% / −45%**，是**平滑累积/衰减**，不会被单一维度带飞

### 3.3 ⚠️ "贝叶斯"是名不符实的

全模块**没有似然、没有先验、没有后验**，没有任何概率模型。它就是"手写分档 + 乘性更新"。
模块 docstring（`:1-7`）的自称会误导读者 —— 这是**审计 P1 的核心指控**（"称贝叶斯但无似然/先验/后验"）📄。

## 4. 第三层 · 生命周期状态机（六阶段）

两个正交状态量：

- **`status`**（进出态）：`sleeping → triggered → tracking → eliminated`
- **`phase`**（生命周期）：`early → growing → mature → alarming → decaying`

### 4.1 转移表

| 转移 | 触发条件 | 位置 |
|---|---|---|
| sleeping → **triggered** | §2.1 四条件 | `:491-493` |
| triggered → **tracking**(early) | 次日，`days=1` | `:496-505` |
| early → **growing** | MA21 > MA89 且间距 ≥ **0.5%**（首次）/ **1.0%**（二次），连续 **3 / 5** 日确认 ⇒ 记 `entry_price` | `:598-644` |
| growing → **mature** | `R = (最高价 − entry_price)/entry_price` **≥ 8%** ⇒ **不可逆**（mature 无回退分支） | `:646-673` |
| growing → **early** | R < 8% 且 MA21 < MA89 连续 3 日 ⇒ "假成长退回" | `:675-694` |
| mature → **alarming** | **2-of-4 预警** 或 **保底**（MA5 < MA21 且间距 ≥0.5%，连续 2 日） | `:700-755` |
| alarming → **mature** | 创新高记基线 + 连续 3 日不跌破基线 ⇒ "预警消退" | `:786-818` |
| alarming → **eliminated**(decaying) | MA21 < MA89 连续 3 日（死叉确认） | `:768-781` |
| eliminated → **triggered** | 可重新入场（`is_reentry=True`） | `:484-488` |

**"成熟期不可逆"是靠"没有写回退分支"实现的**，不是靠显式标志位。

### 4.2 2-of-4 标准预警 `_check_alarm_signals()` `:824-881`

| 信号 | 定义 | 常量 |
|---|---|---|
| **A1 宽度衰减** | 当日宽度（MA13 基准）连续 **3** 日 < 近 5 日均宽 | `ALARM_BW13_DECLINE_DAYS=3` |
| **A2 拥挤过热** | 拥挤度分位连续 **3** 日 > **90%** | `ALARM_CROWD_HOT_DAYS/PCT` |
| **A3 大实体阴线** | 等权均收盘/均开盘 − 1 < **−5%** | `ALARM_BIG_SHADOW_PCT=0.05` |
| **A4 单日巨量** | 当日成交额 / 近 5 日均量 > **1.5** | `ALARM_HUGE_VOL_RATIO=1.5` |

⇒ 需 **≥2 个同时成立**（`ALARM_MIN_SIGNALS=2`，`:879-881`）才进预警。

### 4.3 剔除规则（tracking 态通用；前 3 日 `GRACE_DAYS` 豁免）`:519-554`

| 规则 | 阈值 |
|---|---|
| 宽度连续 **2** 日 < 15% | `BREADTH_ELIMINATE_DAYS` |
| 跟踪超 **30** 日 | `MAX_TRACK_DAYS` |
| 分数连续 **3** 日 < **30** | `ELIMINATE_SCORE/DAYS` |

（保护期内**分数照常更新**，只是豁免剔除 `:516-520`。）

## 5. 第四层 · 池子与台账投影

### 5.1 跟踪池 `get_tracking_pool(min_score=50)` `:945-969`

取 `status ∈ {tracking, triggered}` **且 `score ≥ 50`**，按 `阶段 → 置信度 → 分数` 排序。
这是与日报/富途同步用的名单（⚠️ **门槛 `50` 硬编码在 3 处且两处用了不同常量名**：`industry_tracker.py:945/989`（默认参数）、`report_sections.py:39`（`SYNC_SCORE_MIN`）、`sync_industries_to_futu.py:20`（`STORY_SCORE_MIN`）⇒ 漂移风险）。

### 5.2 台账投影 `src/signals/sources.py::_snapshot_tracker`

读 `tracker_report.csv` → 筛 `status == "tracking"` → 以 **`signal_date` 为入场事件**入账
（`obs_type="event"`）⇒ 每日重复快照自动去重。

### 5.3 🔴 一个结构性限制（设计层面，不是 bug）

状态只存在 `tracker_state.json`，**只保存当前值** ⇒ **历史无法无损重建**。
因此台账**只能向前快照、不能回填**。这正是它至今标记"⏳ 待观察、样本不足"的**根本原因**
——不是"还没到时间"，而是**这个架构产不出可比的历史样本**，除非改成"每日全量落盘快照"。

## 6. 设计原理总括

```
深睡(前20日均宽<45%) × 惊醒(单日>1.5%)
        ↓   ← 核心假设：超跌 + 异动 = 反转起点
   S₀ = 沉睡深度放大器 × 涨幅基础分          （乘性：越深睡、越猛涨 ⇒ 越强）
        ↓
   每日 Sₜ = Sₜ₋₁ × λ(Δ宽度, 涨幅, 量能, 拥挤度)   ← 加权几何平均，平滑累积
        ↓
   early ──均线金叉(3~5日确认)──→ growing ──R≥8%──→ mature（不可逆）
                                    ↑↓ 假成长退回        ↓ 2-of-4 预警
                                                       alarming ──死叉──→ decaying
                                                          ↑↓ 创新高+3日不破 ⇒ 退回 mature
```

**它的世界观**：反转不是一个"点信号"，而是**有阶段的过程**；每个阶段看不同的证据
（早期看均线、成长期看涨幅、成熟期看过热、预警期看是否创新高）。

## 8. 验证状态与评估门槛

> ### ⚠️ 但存在一份「孤儿回测文件」，它**不构成评估** —— 三条理由

> 时间早于 P2-4 PIT 修复（2026-10-01）与复权价修复（2026-10-05）。

> ⇒ 它**不是**"待观察积累的样本"，也**不是**"已验证的证据"；按 §0 五条门槛，它是**未评估**。
