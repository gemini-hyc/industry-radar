# 2026-10-09 主线「阶段无记忆」—— P0 只读记忆字段上线

## 1. 局限性

`stage` 是**单日查表**：`heat_ratio × excess_ma20 → {蛰伏/启动期/过渡/加速期/见顶期/瓦解期}`，
输入只有当日快照，无任何跨日状态 ⇒ "刚热 3 天" 与 "热了半年" 可能得到同一个标签。

复核后确认，记忆是被**两级**破坏的：

| 层级 | 现象 | 性质 |
|------|------|------|
| 显示层 | `consec_days` 只在 `min_consecutive_days` 窗口内回扫，取值被锁死 ≤3 | 缺陷：与注释「末尾连续天数」的意图不符 |
| 概念层 | heat 是慢变量（20日均值 ÷ 2020 起扩张均值），`Spearman(hot_age, heat)=+0.528` ⇒ "见顶期"统计上≈"热得久"（87% 的见顶期样本段龄>10天） | 设计属性，非缺陷；但记忆以**不可读**方式被编码 |

## 2. 本次改动（P0）

**原则：只加只读字段，不动任何判定。** 依据 2026-10-09 探针——记忆类特征的预测力不成立
（段龄 IC≈+0.07、`run_len` IC≈+0.001、`cum_excess_seg` IC≈+0.05），其价值在**可解释性**。

`scripts/mainline_detector.py`
- 修正 `consec_days`：**真实尾部段长，不截断**（新增 `trailing_true_count`）
- 新增 4 个只读字段：`hot_age`（热度段龄）、`heat_slope20`（热度 20 日变化）、
  `cum_excess_seg`（本段累计超额）、`is_new_mainline`（当日首次达门槛，1-bit 事件）
- 控制台对「放量不涨」（热度升但段内累计超额为负）自动告警

`src/daily_review/report_sections.py`
- 主线表新增「连续达标/段龄」「段内累计超额」两列；Top5 表新增「段龄」「段内累计超额」
- 订正表头口径错误：原文「热度 > 1.3x 且 60 日超额 > 0」与实现不符，
  实际为「热度≥1.3x 且 20日超额≥0.3%/日 且 超额胜率≥60% 且 连续≥3交易日」
- 表下加口径脚注，明写**无预测力、不构成买卖建议**

`tests/_common.py`
- 列契约同步：新增 4 列（mainline_detection 15 → 19 列）

## 3. 实测验证

新旧探测器对**同一数据根**逐列比对：

```
group_id / heat_ratio / excess_ma20 / winrate / is_mainline /
is_mainline_raw / stage / style / min_consecutive_days   全部一致=True

consec_days  旧（截断）{0,1,3}   新（真实）{0,1,6}
```

`is_mainline` 判定逐字未变的理由：`run_len >= N` ⟺ 末 N 日全部达标（含回滚模式与早期分支）。

`pytest` 93 passed / 1 skipped。

## 4. 明确不做（附依据）

- **P1（热度分母改滚动 250 日）撤回**。原称可「解除 heat 与段龄的混淆」，A/B 实测证伪：
  `Spearman(hot_age, heat)` 仅 **+0.507 → +0.366**，仍强正相关。机制性原因——能持续热的群，
  其 20 日均值天然高于任何窗口均值，换分母压不掉。成本（全量重标 + 阈值重定 + 基线重建）
  确定而收益已被否定主体 ⇒ 不做。
- **P2（二维状态机 + 迟滞）不做**。段龄结论**定义敏感**：热度段龄口径得"新段最差、单调升"，
  三条件段龄口径得"新段不差、U 形"——同批数据结论翻转，状态机没有地基。
