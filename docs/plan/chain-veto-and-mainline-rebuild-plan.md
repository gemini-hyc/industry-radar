## 0. 为什么两件事合并成一个项目

交接文档里两个已知缺陷，表面是两件事，本质是**同一个**：

| 缺陷 | 出处 | 一句话 |
|:--|:--|:--|
| **A** 74 条链"否决权未作用于名单" | 交接 §6.4 | 74 条链只走完双通道的第一条腿（语义定家族），第二条腿（共振验证）从未作用于它的生成 |
| **B** `mainline` 方法"测错对象" | 交接 §5.2-#6 / 方法论 §2.2 | 全市场相关聚类 = beta 聚合产物，聚出来的是"谁跟大盘像"，不是产业链 |

**合起来看**：方向群（B）缺的是"正确的家族定义"，而链（A）缺的是"验证"。而**链的家族定义恰好就是方向群应该用的那把尺子**——B 的改造方向（链内残差 + 最小成员数 + 连续强度量）本质就是"把方向群的定义权从自由聚类换成语义链"。所以 A 与 B 共享同一块地基：**一条经过验证的链清单**。

⇒ **A 是 B 的前置**：先验证出"哪些链站得住"（A），才能把这些链当作方向群的定义（B）。合并立项，顺序 A → B。

## 1. 目标与非目标

### 目标
1. **A**：给现有 74 条锁定链补做否决权验证，产出**三档分级**（已验证结构 / 观察中 / 未通过），让"哪些链可信"第一次有证据。
2. **B**：把 `mainline` 的方向群定义从"全市场相关聚类"换成"语义链 + 最小成员数 + 共振强度连续量"。

### 非目标（明确不做，防范围蔓延）
- ⛔ **不重建先验名单**。74 条链是外部篮子程序推导 + 已锁定，改动它必须另立项并重新锁哈希（`measure_chain_resonance.py` 会校验 sha256）。
- ⛔ **不做命中率/漏检率检验**。名单 `post_hoc=true`（过滤规则在看过"7 对幸存名单"之后写的）⇒ 任何"找到了多少真链"的统计都不可信（review §12.6）。
- ⛔ **不调阈值**。热度过 1.3 / 超额 0.3 / 胜率 60% 等判定阈值不在本项目范围。
- ⛔ **不删任何现有装置**，不改十步链的既有产物契约。

## 2. 项目 A：74 链否决权验证

### 2.1 要补的是哪条腿

双通道 = 定义权（语义定家族）+ 否决权（共振跨段稳定才转正）。74 条链只做了前者，本步补后者：

> **对每条链，检验"链内成员的残差相关"在三段（2020-21 / 2022-23 / 2024-26）上是否同质**——同质=真结构、单调增强=新生、衰减/闪烁=不稳定。

### 2.2 复用什么（已全部存在，均为单一实现）

| 设施 | 位置 | 用途 |
|:--|:--|:--|
| `classify_three_segment(rs, ns)` | `src/evaluation/inference.py:341` | 三段相关 → 结构/新生/衰减/闪烁（Cochran Q，Fisher-z，df=2 闭式，无 scipy 依赖） |
| `cochran_q_homogeneity` | 同上 `:310` | Q 检验底层 |
| `group_statistic(Cm, idx)` | `src/resonance/group.py:32` | 群级统计量 = 链内所有对的**带符号**残差相关均值 |
| `stratified_null` / `zscore` | `src/resonance/group.py:86/110` | L1 分层零分布 → 跨链可比的 z 值 |
| `residualize` | `src/resonance/measure.py:42` | 收益层残差化 `r̃ = r − Σβf` |
| `assert_prior_locked` | `scripts/measure_chain_resonance.py:48` | 名单哈希校验（保证测的是锁定版） |

### 2.3 需要新写的（唯一新增物）

一个**只读**脚本 `research/chain_veto_verification.py`（沿 `research/chain_three_class_qtest.py` 的形态：零写入数据根，输出到 `_local_dev/`）：

```
1. 校验并加载锁定名单（74 链 / 335 成员）
2. 加载收益面板（131×1636）+ ~/quant-data 内的风格因子面板
3. 逐段（3 段）各自重剥 beta（in-sample，与 chain_three_class_qtest 同口径）：
   - 每段算残差相关矩阵
   - 对每条链取 group_statistic（链内带的符号残差相关均值）→ r_seg1/2/3
4. classify_three_segment([r1,r2,r3], [n1,n2,n3]) → 分类
5. 分层零分布 → z_adj（跨链可比），exceedance
6. 落盘三档分级表 + 打印"实测 X vs 噪声期望 Y"
```

⚠️ **口径要害（写代码时必须钉死）**：验证通道用 **in-sample beta**（每段各自重剥），
与测量通道的 **out-of-sample beta**（`measure.py`，用 [t−W,t−1] 估计）**不是一回事**。
`measure.py` 顶部已明文警告"两者不可混用，混用即第三次'两套口径'翻车"。本脚本属验证通道，必须走 in-sample。

### 2.4 输出与三档判据

| 分类（classify_three_segment 输出） | 归入档位 | 含义 | 下游处置 |
|:--|:--|:--|:--|
| `structure`（Q 同质 p>0.05） | **已验证结构** | 三段同水平，真链证据最强 | 可作 B 的方向群候选 |
| `emerging`（不同质 + 严格递增 + 每级超噪声） | **观察中** | 新生链，不转正 | 只观察，不进 B 群定义 |
| `decaying` / `flicker` | **未通过** | 衰减或闪烁，不稳 | 不进 B 群定义；**不删链**（仅在分级表标出） |

**报告纪律**（沿用 spec ⑥）：一律写「实测 X 条 vs 噪声期望 Y 条」，⛔ 不写「X 条稳定」。

### 2.5 ⚠️ 本步的证据地位（必须写在输出文件头）

> **本验证只在"对象清单"层面自洽，不构成方法有效性证据。**
> 原因：名单 `post_hoc=true`。它回答的是"已锁定的这 74 条里，哪些共振结构最结实"，
> ⛔ **不回答**"共振方法发现了多少真链"。后者需要一份**先于查看结果**撰写的外部先验（当前没有）。

## 3. 项目 B：`mainline` 重建

### 3.1 病根与改造方向

方法论 §2.2 实测：全市场剥 beta 后行业间相关均值 **0.410→−0.006**，聚出 **58 行业巨群**，
250 日重聚归属保留率仅 **47.3%** ⇒ 自由聚类聚的是 beta。**改造方向**（§2.2 原文，未执行）：

> **链内残差 + 最小成员数门槛 + 强度连续量**

### 3.2 拆成三个可由小到大的改动

| 子项 | 内容 | 风险 | 依赖 |
|:--|:--|:--:|:--:|
| **B1** 最小成员数门槛 | 现在**无**任何门槛，会出现"1 个行业的方向群被判定为主线"（代码注释明说）。加一道下限（如 ≥3 成员） | 低，独立可做 | 无 |
| **B2** 群定义换成语义链 | `cluster_industries` 的全市场自由聚类 → **读锁定链名单作为群定义**（即把"方向群"改成"链"） | **高**（改变日报口径） | **A** |
| **B3** 共振强度连续量 | 群统计量从"平均涨跌幅"补上"链内残差共振"（连续量），不作硬分组 | 中 | A |

### 3.3 B2 的关键风险：口径变更会动日报

现状日报的"群14 / 群18"是自由聚类产物，与链名单**编号体系不兼容**。替换后：
- 日报"方向群"章节的群编号、成员、数量全变（23 群 → 74 链或验证子集）；
- `mainline_detection.csv` 的列语义变化 → 台账、`sources.py` 快照、`tests` 列契约都可能转红。

⇒ **B2 必须走"新旧并行双跑 + 逐列比对"**（沿用本项目"不靠断言靠实测"纪律）：
先产出新版、与旧版并列展示一段时间，确认判定变化可解释后，再决定是否切换。⛔ **不得直接替换。**

### 3.4 B 的定位约束

`mainline` 现在是 `status=observational`（§12.3 裁决）。改造**不等于转正**——
重建后仍需按台账评估（超额、非重叠 t、IS/OOS 切分）检验，通过前不得作交易依据。
`status_note` 里"⛔ 不得用于链假设"这条**在 A/B 都完成且重新评估前继续有效**。

## 4. 红线（全程禁令，来自既有裁决，不得违反）

1. ⛔ **未做风格控制时不得放开 `within-L1` 限制**（实测会放进约 80 个风格对，比现状更糟）。
2. ⛔ **PC 投影只作辅助诊断、不作判据**。
3. ⛔ **`post_hoc` 名单不得用于命中率/漏检率检验**。
4. ⛔ **验证通道（in-sample）与测量通道（out-of-sample）beta 不得混用**。
5. ⛔ **旧三分类计数（66/77/84+21 等）一律作废**，须从锁定 spec 重算。
6. ⛔ **不改阈值、不原地改锁定名单**（改名单须新建 v2 并重新锁哈希）。
7. ⛔ **不得通过调参"修复"** `mainline`（§12.3 note 明文）。

## 5. 依赖与建议顺序

```
项目 A（验证 74 链）────┐
                        ├──→ 项目 B2（群定义换成已验证链）
项目 B1（加成员数门槛）─┘
                        └──→ 项目 B3（加共振连续量）
```

- **B1 无依赖**，可最先做（小、可独立验收）。
- **A 无依赖**，是 B2/B3 的前置，建议紧随 B1 或并行。
- **B2 依赖 A**（需要"已验证结构"的链清单）。
