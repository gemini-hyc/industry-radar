## 模块间逻辑关系（v2.1 2026-07-22）

```
T+0 决策链（当日收盘后运行）：
  模块一（市场体检）  → 定调子：进攻 or 防守
          │              ETF宽基资金流作为资金立场第二信号
          ▼
  模块二（行业跟踪）  → 定方向：钱在哪
          │              ETF行业资金流独立排名
          ▼
  模块三（个股推选）  → 定标的：买什么
          │
          ▼
  模块四（持仓体检）  → 定去留：卖不卖
          │
          ▼
  模块五（明日预案）  → ← 前序模块汇总成行动计划

T+1 验证链（次日盘前运行）：
  模块六（关键事件）  → 定信心：事后验证
          │              融资融券、大宗交易 T+1 就绪
          │              用事件层独立数据验证昨日 M1~M5 的判断
          │              验证结果供 M7/M8 使用
          ▼
  模块七（信号复盘）  → 累积型，≥10交易日信号 → 信号靠谱吗
          ▼
  模块八（学习笔记）  → 人的判断反馈给系统
```

**v2.1 架构变更（2026-07-22）：**
- **模块三移至 M6 之后**：融资融券和大宗交易数据需 T+1，无法参与当日决策。放在明日预案之后，角色从"决策输入"变为"事后验证"
- **T+0 和 T+1 分层**：M1/M2/M4/M5/M6 在当日收盘后完成决策链，M3 在次日盘前验证昨日判断
- **ETF 资金流归位**：宽基 ETF → M1（资金立场双信号），行业 ETF → M2（独立排名），两者均为 T+0
- **模块三待重新设计**：代码保留，需基于新的"事后验证"定位和 T+1 时序重新设计

## 模块一：市场体检

**核心问题：** 今天是该进攻还是防守？

**产出子模块：**

| 子模块 | 内容 |
|:---|:---|
| 等权市值分层 | 5档分层表 + 全市场EW汇总 + 背离检测 |
| 市场宽度 | 涨跌家数、分板块涨跌停、创20日新高/新低、站上MA20占比、涨跌成交额比 |
| 量价诊断 | 个股量价分布表驱动健康度判定 |
| 阶段判定 | 暂未启用 |
| 仓位建议 | 暂未启用 |
| 健康度评价 | 五维度独立评价（资金立场含行情面+ETF资金面双信号对照） |

**交付形式：** 飞书消息（Markdown） + `data/reports/YYYY-MM-DD_module_01_conclusion.json`

## 技术原则

1. 每个模块一个独立 Python 脚本
2. 模块按数据依赖时序调度（T+0: M1/M2/M4/M5 → T+1: M3 → M6）
3. 报告推送到飞书，Markdown 格式
4. 大盘仓位系统、行业反转系统、因子库保持独立，复盘系统只读其产出
5. 所有模块产出使用中文
6. 不依赖 LLM，纯 Python 计算（公告速览除外）
7. M1/M2 产出结构化 JSON 结论文件，供下游模块消费
