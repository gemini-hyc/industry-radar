# regime 口径修复（P2-1）

> 日期：2026-10-01 ｜ 对应审计文档 P5「regime 分类的"结构性"维度实际已死」
> 前置：P0+P1 见 `docs/changes-2026-10-01-p0p1.md`

---

## TL;DR

`rank_consistency` 有一处 **ddof 口径不一致的 bug**，使随机排名的基线从 0 漂移到 **−0.25**。
分类阈值按 0 中心设定（0.3 / 0.4），于是在 1636 个交易日里**零次**触发，
「结构性 / 偏强结构性 / 边缘结构性」成为**死类**，报告里从未出现过。

已修复并重校准阈值。修复后 8 类全部出现（最小 3.0%）。
**同时发现该指标作为连续变量对未来的预测力为零** —— 已在代码与本文档中明确标注，防止误用。

---

## 一、问题诊断

### 1.1 根因：ddof 口径不一致

原 `rolling_rank_corr`：

```python
rank_var = rank_df.var(axis=1)                          # ddof=1（样本方差）
max_var  = (n_ind**2 - 1) / 12 * (1 - 1/len(window_dates))   # ddof=0（总体方差）口径
consistency = 1 - mean_rank_var / max_var
```

分子是 **ddof=1** 的样本方差，分母却是 **ddof=0** 口径下随机排名的期望方差
（`σ²·(1-1/W)`，σ²=(n²-1)/12），两者相差因子 `W/(W-1)`。于是：

- 随机排名下 `consistency ≡ 1 - W/(W-1) = −1/(W−1) = −0.25`（W=5），**而非 0**
- 实测全历史均值 **−0.2456**，与理论值精确吻合 → **bug 确证**

**受控实验**（同一份纯随机数据，131 行业 × 120 天）：

| seed | 原口径均值 | 新口径均值 |
|:--:|:--:|:--:|
| 42 | −0.2581 | −0.0009 |
| 7 | −0.2620 | −0.0038 |
| 2024 | −0.2618 | −0.0031 |

修复后的映射关系为 `new = 0.2 + 0.8 × old`，实测 1631/1635 天精确成立
（4 天偏差属窗口预热期，非 bug）。

### 1.2 效度检验：指标本身没有预测力

修好 bug 只解决"能不能用"，不解决"有没有用"。用**超额收益**（`fwd_excess_20`，非绝对收益）
检验全历史 2230 条冷区信号：

**连续指标四分位 vs 20 日超额：**

| 指标 | Q1 | Q2 | Q3 | Q4 | 判断 |
|:---|:--:|:--:|:--:|:--:|:---|
| rank_consistency（修复后） | +0.14pp | +0.62pp | +0.66pp | −0.19pp | 倒 U 型，非单调 |
| rank_autocorr | +0.39pp | +0.24pp | +0.67pp | −0.07pp | 非单调 |
| top5_conc | +0.43pp | +0.74pp | +0.15pp | −0.07pp | 非单调 |
| up_pct | −0.01pp | +0.30pp | +0.71pp | +0.23pp | 非单调，极差 <0.8pp |

**领先-滞后检验：** rank_consistency → 次日排名延续性 Pearson **−0.029**；
→ 5×5 横截面动量自相关 Pearson **−0.034**。

> ⚠️ **一个重要更正**：若用**绝对收益**（`fwd_ret_20`）分组，`up_pct` 会呈现
> 1.89%(@<20) → 4.07%(@>80) 的"单调上升"，看似很有区分度。改用**超额**后，
> 该差异塌缩到 0.8pp 以内且不再单调 —— 说明原来看到的区分度**主要来自市场 beta，
> 不是信号自身的 alpha**。任何以绝对收益做分组检验的结论都需要重新审视。

### 1.3 附带发现：top5_conc 与 up_pct 高度共线

| 区间 | n | tc ≥ 0.30 | tc 中位数 |
|:---|:--:|:--:|:--:|
| up < 30 | 421 | 408 | 0.540 |
| up 30–50 | 385 | 235 | 0.315 |
| up ≥ 50 | 829 | 17 | 0.185 |

普涨时涨的行业多，Top5 占比自然低；普跌时少数行业涨，Top5 占比自然高。
**两者本质上都在度量"市场广度"，不是独立维度。** 这解释了为什么原
"结构性"条件里的 `tc > 0.30` 几乎没有筛选作用（`up<50` 时 61–97% 的日子天然满足），
也解释了为什么「偏强结构性」（`up≥50 & tc≥0.30`）在原设计下只有 **17 天**。

**结论：`rank_consistency` 是分类器中唯一的独立"结构"判据，而它恰好无效。**

## 二、修复内容

### 2.1 阈值对照

| 参数 | 旧值 | 新值 | 依据 |
|:---|:--:|:--:|:---|
| 归一化基准 | `(n²−1)/12 × (1−1/W)` | `(n²−1)/12` | 与分子的 ddof 对齐 |
| 结构性 rc 门槛 | > 0.3 | **> 0.05** | ≈ 全历史 q80（新锚点下 0.3 不可达） |
| 偏强/边缘 rc 门槛 | > 0.4 / 0.2~0.3 | **> 0.02 / 0.0~0.05** | 同上 |
| 偏强结构性 up 区间 | `50 ≤ up < 60` | **`up ≥ 50`** | 原区间与高 rc 无交集（仅 3 天） |
| 偏强结构性 tc 门槛 | > 0.30 | **> 0.20** | 同上 |
| 轮动 rc 门槛 | < 0.2 | **< 0.0** | 新锚点下 0.0 = 随机水平 |

阈值选取目标：**让每个类别都有足够样本覆盖（各类 ≥ 3%）**，而**不是**优化预测力
（该指标无预测力，见 §1.2）。

### 2.2 其他改动

- 新增 `rank_autocorr` 列（docstring 一直声称有、代码里从未计算）。
- 加 `main()` 结构，模块可安全 import（原为顶层代码，import 即执行）。
- 新增**写入护栏**：新结果行数 < 旧文件 90% 时拒绝写入（防输入被截断后覆盖健康历史）。
- 修复 `rank_var` 的计算轴（原实现对 `ind_code`/日期维度处理正确但语义隐晦，已显式化）。
- 性能：排名按日期预建一次，避免循环内反复过滤整表。

## 六、已知遗留

1. **`rank_consistency` 无预测力**（§1.2）。本次只修 bug 与阈值，**未解决其无效性**。
   regime 应作为【市场状态描述】使用，**不得作为交易信号或预测依据**。
   代码 docstring 顶部已有显式声明。
2. **`top5_conc` 在上涨行业不足 5 个时返回负值/极端值**（实测 min=−8.33，10 天为负，
   均出现在 up<2% 的日子）。本次仅记录不修改 —— 修改会波及全部历史标签，应单独评估。
3. **「结构性」类样本过小**（42 条信号），其负超额不稳健，需样本外验证。
4. **分类器实质上是"市场广度分类器"**：`up_pct` 与 `top5_conc` 共线，
   `rank_consistency` 无效。若要真正区分"结构"，需要引入新的独立判据
   （候选：行业内收益离散度的变化率、龙头-跟随的领先滞后结构等）。
5. `month` 派生列仍被写入 parquet（历史遗留，无害但不够干净）。
