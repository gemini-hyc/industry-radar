## P2-1 · regime 口径修复（已完成并验证）

用户批准「从 regime 口径修复开始」。诊断中发现原方案不完整，做了超出预期的排查。

### 诊断结论

1. **根因确证**：`rolling_rank_corr` 的 ddof 基准不一致 —— 分子 `rank_df.var()` 是 ddof=1，
   分母 `(n²−1)/12×(1−1/W)` 是 ddof=0 口径 → 随机排名下 `consistency ≡ −1/(W−1) = −0.25`。
   实测全历史均值 −0.2456 与理论吻合。
2. **受控实验**（同一份纯随机数据，131×120）：原口径 −0.258 / −0.262 / −0.262；
   新口径 −0.001 / −0.004 / −0.003。稳定数据新口径 +0.9745。**bug 与修复均确证。**
3. **效度检验（负面结论）**：`rank_consistency` 对未来的预测力为零
   （→ 次日排名延续性 r=−0.029；→ 5×5 横截面动量自相关 r=−0.034）。
   用**超额**口径检验，rc / ac1 / tc / up **四个连续指标全部非单调**。
   ⚠️ **自我更正**：此前用**绝对收益**看到 up_pct "1.89%→4.07% 单调上升"，
   改用超额后差异塌缩到 0.8pp 以内 —— 那是市场 beta，不是 alpha。分组检验必须用超额。
4. **附带发现**：`top5_conc` 与 `up_pct` 高度共线（up<30 时 tc 中位数 0.54；up≥50 时仅 0.185），
   两者都在度量"市场广度"。原"结构性"条件里的 `tc>0.30` 几乎无筛选作用。
   → **rank_consistency 是分类器中唯一的独立结构判据，而它恰好无效。**

### 改动（`scripts/regime_classifier.py`，单文件）

修 ddof 基准；重校准阈值（rc 门槛 0.3→0.05；偏强结构性 up 区间 `50–60`→`≥50`、tc `0.30`→`0.20`；
轮动 rc `0.2`→`0.0`）；新增 `rank_autocorr` 列；加 `main()` 结构（模块可安全 import）；
加写入行数护栏（新结果 < 旧 90% 时拒绝写入）；docstring 顶部加效度声明。
